# BCT 工作台 Agent 开发

把用户的自然语言指令变成可核验的原生页面操作。此 Skill 面向开发和维护助手；系统内运行的收益互换业务 Skill、工具实现和页面适配器是不同层，不能互相替代。

## 开始工作

先读目标项目的 `AGENTS.md` 与 `agent.md`，核对本次需求、现有授权和实际部署版本。查找 `spring-ai-starter` 的实现，不假定本仓库包含可运行服务。

按任务读取必要参考：

- 理解链路、工具注册、身份或扩展成本：读 [architecture.md](references/architecture.md)。
- 开发页面动作、排查弹窗和保存误判：读 [page-adaptation.md](references/page-adaptation.md)。
- 适配合约、标的物、交易对手或机构：读 [business-mapping.md](references/business-mapping.md)。
- 找代码、验证、部署或回滚：读 [verification-and-delivery.md](references/verification-and-delivery.md)。

## 项目接入边界

本项目用户选择“提前适配”，接受在原工作台 `index.html` 加载独立助手脚本。除用户后续明确变更外：

- 对原业务前端发布文件的修改，仅限入口中的助手引用与必要加载配置。不修改原业务 JS/CSS、路由定义或组件，不重编业务前端。
- 页面导航、筛选、填单、详情操作放在 Agent 提供的独立脚本中，复用现有控件和事件；不操作 React/Vue 私有状态，不让模型提供任意脚本、URL 或请求头。
- 原生校验、保存、弹窗关闭与列表刷新由原系统处理。当前页面工具只填写、查询和回读，最终保存由用户操作。
- 既有脚本会观察指定只读请求。这是运行时介入，不能称为“完全零侵入”；本 Skill 不授权新增或扩大请求拦截。
- 本 Skill 不包含生产地址、凭据或业务数据，也不授予部署、提交或审批权限；实际动作以当前会话授权为准。

## 证据驱动的开发流程

1. **先看实际代码与接口。** 没有源码时读取已授权服务器的 HTML、JS 构建包、路由和请求封装；OpenAPI 优先读本地快照。必要时分析用户授权的后端 JAR，记录实际版本。构建包、反编译结果不等于完整源码。
2. **建立字段映射。** 对每个条件记录业务含义、页面标签/字段、控件类型、接口字段、枚举、单位、默认值、证据来源。页面模型与接口 DTO 分开；不能只凭 Swagger 生成页面点击逻辑。
3. **参数化已有能力。** 新状态、日期值和组合优先复用已有动作；新增控件或业务步骤才扩展适配器。未知条件明确返回不支持，不能静默省略。
4. **用页面消除不确定性。** 静态证据不足或与运行行为不一致时，操作原生页面核对候选、联动和请求。交付页面功能前仍要做真实页面验收。
5. **等待结果，再报告。** 页面动作返回实际路径、字段、查询条件与错误；只发出命令或点击不代表完成。失败时回读已经发生的变化，不能把部分填写说成完全没有操作。

## 必须保留的行为

- 用户说“给我操作页面”时，执行页面工具，不能只生成后台草稿或用 HTTP 查询结果冒充页面已操作。
- 用户说“先填，我手动调整”时，先填有依据且已适配的字段，不用后台 DTO 的全部必填项阻挡弹窗打开。经济条款未知就保留待补；字段没回读不等于页面为空。
- 合约簿记通过列表的“创建合约”打开“创建一般合约”原生弹窗，背景保持列表。不要用整页一般合约录入路由替代。
- 页面状态使用实时 DOM 和当前回执。`submittedByAgent=false` 只表示助手没提交；旧草稿、URL 不变、表单保留内容都不能证明用户没保存。
- 已识别的只读详情可以按当前导航意图关闭。未知或编辑弹窗需保护；本任务创建的表单可以继续填写，空白弹窗可按当前规则接管，不能无差别阻止所有弹窗。
- 产品联动短暂加载时等待稳定；用户点击原生确认、表单被关闭/替换、出现未知嵌套弹窗时停止自动填写。不把联动加载当成真实提交。
- 认证、任务与标签页归属、字段白名单、提交权限属于执行器约束。调整 Skill 不会自动改变这些代码，也不能靠对话绕过。

## 交付口径

清楚说明改了 Skill、工具协议还是执行器，说明原业务前端实际修改范围。区分“已填入页面”“业务校验通过”“用户说已保存”“后台确认保存”四种事实。

报告已验证的动作和未验证部分；保存生命周期只有源码证据时，不能宣称真实交易保存已验收。保存经脱敏的验收记录和必要截图；涉及可恢复部署时提供备份与回滚方法。
