# 原生页面、弹窗与状态判断

## 先找用户实际使用的入口

同一张表单可能同时被整页、弹窗、抽屉复用。字段相同不意味着关闭、保存后导航和列表刷新行为相同。

在收益互换场景，用户要求的是合约列表上的“创建合约” → “创建一般合约”弹窗，背景保持列表。此前误用整页录入路由，造成用户保存后仍在录入页；正确修复是改 Agent 入口，不改业务组件或强制关闭窗口。

核对入口时记录：现有路由/按钮、弹窗标题、承载组件、创建/编辑模式、保存成功回调、关闭回调及列表刷新。静态代码无法确认的部分再用页面核对。

## 表单适配流程

1. 读取实时页面，判断是否可导航或已有可复用表单。
2. 使用原生入口打开目标表单，限定在已识别弹窗/抽屉内部查找控件。
3. 等待模板初始化、候选加载、表单重建和字段联动完成；不要仅凭控件出现判定可填。
4. 按依赖顺序填写，例如产品类型 → 交易簿/对手方 → 资金账户 → 标的与经济条款。具体顺序以实际联动为准。
5. 搜索下拉使用精确匹配；不猜系统 ID，不把第一个近似名称当作目标。
6. 每次动态变化后重新定位控件；回读实际值与用户意图比较。
7. 返回实际已填字段、未完成项、表单类型与真实状态。未知必填项可以待补，不阻止填写其他已知项。

数字使用准确的十进制字符串，单位转换由已确认规则处理。日期控件需等待面板关闭和原生确认，避免后一字段点击落在前一日期面板。

## 页面状态与保存事实是两个维度

| 证据 | 可得结论 | 不能得出的结论 |
| --- | --- | --- |
| `NO_FORM` / `EMPTY` | 没有受保护内容，按当前规则可离开 | 某笔交易已经保存 |
| `CONTENT_PRESENT` / `CHANGED` | 有内容或有变化，需要保护 | 用户从未保存 |
| `submittedByAgent=false` | 本次助手未提交 | 用户没有手工提交 |
| 历史 `pageDraft` | 过去请求填写的意图 | 当前页面内容或保存状态 |
| 用户本轮说“已保存” | `USER_REPORTED` 的人工声明 | 后台保存已核验 |
| 真实成功回执/精确记录核对 | 对应记录的保存证据 | 已审批、已结算或已支付 |

保存后 URL 可能不变，表单也可能保留内容。点击确认可能触发校验失败，因此点击本身不是保存证据。

既有 `acknowledge_saved_form` 只针对工具支持的保留内容场景：核验用户本轮明确陈述，记录当前表单基线，之后再编辑使基线失效。它不能伪造保存回执，也不能用于擅自关闭仍打开的原生创建弹窗。

## 不要把所有弹窗当成阻塞

| 当前现场 | 处理 |
| --- | --- |
| 已识别只读合约详情，无业务编辑/提交或未知嵌套弹窗 | 用户要求导航时，可点击其原生关闭后继续 |
| 空白原生创建弹窗 | 按当前接管规则使用，不重复打开 |
| 当前任务拥有且仍连接 DOM 的创建表单 | 可以继续填写和回读 |
| 非空人工表单、其他任务表单 | 保护内容，不能覆盖 |
| 未识别弹窗或嵌套编辑弹窗 | 停止冲突动作，报告实际阻挡原因 |
| 当前表单关闭或被替换 | 旧归属失效，新建动作重新获取原生入口 |

只读详情中的搜索、分页控件不等于业务编辑表单；也不能只根据弹窗存在就断言“非空”“不是我打开”“用户未保存”。

## 区分联动加载与用户提交

切换产品时，原生组件可能让确认按钮暂时 disabled/loading。若 guard 一见忙碌就失败，会出现“已选产品但后续全没填”的问题。

应在有界期限内等待联动稳定；同时记录用户点击原生确认的独立信号，一旦用户开始确认就停止当前自动填写，把控制权交回原生流程。不能用超时无限等待，也不能拦截或替代用户保存。

本次实现通过原生确认点击版本变化识别用户开始提交；它不是业务成功信号。对于后续新组件，需重新核对键盘提交、确认入口位置等实际机制，不把某个 CSS 或点击方案当成通用事实。

## 查询与回执

带条件查询要处理旧筛选、默认日期和组件重建，按字段组合目标条件，点击原生查询，并核对最终只读请求的条件及业务结果。

- 成功查询：`status=success`、`queryTriggered=true`、`filtersVerified=true`。
- 详情成功：还要有 `detailOpened=true` 和目标记录匹配。
- 表单填写：检查 `applied`、回读 `fields`、`issues`，不等同于业务校验或保存。
- 部分失败：保留实际已打开/已填写的证据，不能全盘报“没操作”。
- HTTP 200 仍可能包含业务错误；零条仅是当前身份和条件下无匹配。
- 超时意味着完成状态未确认，先查现场；不得重复触发潜在副作用，也不得退化成无条件查询冒充成功。

已有请求观察器仅观察明确指定的只读路径，不读取认证头，不修改请求/响应，不保存原始业务响应。不新增写接口监听来推断保存，不扩大拦截面来逃避状态建模。
